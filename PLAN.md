# URacquet.com V2 — Site Plan
*Sept 20, 2026 · Rebuild from scratch as a static site. The Wix site stays live and untouched until cutover.*

## 1. Goal
One fast, indexable, correct website for URacquet Shop that ranks for what Philadelphia tennis players actually search — **racquet stringing Philadelphia / near Penn / University City**, **tennis shop West Philadelphia**, **racquet demo Philadelphia**, **racquet customization** — and converts to a call, a visit, or a drop-off. Every page has one job and one keyword.

## 2. Why static, and why now
- The Wix site has been `noindex` on every page since launch (see `../uracquet-site-audit-2026-09-20.md`). Google has never seen it. A V2 that is *correct on day one* can be indexed within days of going live.
- Static HTML + CSS: no platform, no plugins, no monthly fee, sub-second loads, total control of titles/schema/markup — the three things Wix got wrong. Hosted free on Cloudflare Pages (or GitHub Pages). Mark never needs to log into anything; content edits are text-file edits.
- No JavaScript framework. A ~100-line Python build script assembles pages from a shared layout + per-page content, so header/footer/schema are written once.

## 4. Per-page SEO plumbing (built into the layout, not remembered later)
- One `<title>` (≤60 chars) and `<meta name="description">` (≤155) per page — drafts in the copy deck.
- One H1 per page; H2s for sections; no decorative text in headings.
- Canonical URL per page; `robots: index,follow` (the opposite of the Wix site).
- JSON-LD sitewide: `SportingGoodsStore` (subtype of LocalBusiness) — name, address, geo, phone, email, hours (`openingHoursSpecification`), priceRange, image, `sameAs` (Instagram, University City District listing), `hasOfferCatalog` for the priced services. `FAQPage` on `/services/` and `/demo/`. `BreadcrumbList` on inner pages.
- Open Graph + Twitter card with one branded image (storefront/racket wall).
- Image alt text written by hand; images served as WebP ≤1600px with width/height attributes (no layout shift).
- `sitemap.xml` + `robots.txt` generated by the build.

- **Tone:** confident, technical, friendly — the Court Theory profile's voice. Short paragraphs, prices visible, no stock photos: every image is ours.
- **Hero (home):** `wix_08` (stack of strung racquets) or `wix_06` (Mark at the machine) with the one-line promise and two buttons: *Call (215) 586-3649* · *Get Directions*.
- Layout: single column, max-width ~72ch for text, card rows for services/products, generous whitespace; mobile-first; dark-mode aware via `prefers-color-scheme` (light palette primary).

## 12. Hosting on AWS (keeper has an account) — two routes, both fine
- **Route 1 — Amplify Hosting (recommended, no CLI needed):** AWS Console → Amplify → *Host web app* → *Deploy without Git* → drag the `site/` folder (or a zip of its contents) → app deploys to `https://<branch>.<id>.amplifyapp.com` with HTTPS. Clean URLs (`/services/`) work natively; `customHttp.yml` in `site/` sets the cache/security headers; add a rewrite rule `/<*>` → `/404.html` (404) in *Rewrites and redirects*. Custom domain: Amplify → Domain management → add `uracquet.com` (Route 53 or any DNS; certificate is automatic). Cost: free tier covers this site many times over.
- **Route 2 — S3 + CloudFront (classic):** private S3 bucket + CloudFront distribution with Origin Access Control; ACM certificate in us-east-1; the small CloudFront Function `cloudfront-index-rewrite.js` (viewer-request) so `/services/` serves `index.html`; custom error response 404 → `/404.html`. Deploy with `./deploy-s3.sh` (set `BUCKET`, `DIST_ID`). Cost: ~$0.50/month or less.
- Either way: rebuild with `BASE_URL=<live host>` before the first upload so canonicals/sitemap match; at cutover rebuild with the default and point DNS.

## 13. Hosting on GitHub Pages (keeper has GitHub) — the simplest route of all
- **No AWS, no Cloudflare needed.** GitHub Pages serves static sites free, with automatic HTTPS and custom domains. Fits this site exactly.
- **Setup (once):** create a GitHub repo (public — Pages on a free account requires it; the site content is public anyway), push this folder, then repo *Settings → Pages → Source: GitHub Actions*. The included workflow `.github/workflows/pages.yml` publishes `site/` on every push to `main`. Site appears at `https://<user>.github.io/<repo>/` within a minute.
- **Custom domain (at cutover):** Settings → Pages → Custom domain `www.uracquet.com` (GitHub writes a `CNAME` file into the artifact — for this workflow, add `CNAME` containing `www.uracquet.com` to `site/` via build.py instead); at the registrar add a CNAME `www → <user>.github.io` and four A records for the apex (185.199.108–111.153); tick *Enforce HTTPS*. Rebuild with the default BASE_URL. The Wix site is untouched until DNS moves.
- **Workflow:** edit `content/`/`build.py` → `python3 build.py` → commit `site/` → `git push` → live. Originals in `assets/source/` stay in Dropbox (git-ignored by size); the built site and brand files are committed.
- **Gotcha handled:** `.nojekyll` is written into `site/` so GitHub doesn't run Jekyll (which would drop underscore files like `_headers`).
- Temporary-URL note: on the `<user>.github.io/<repo>/` URL the site lives under a sub-path; links here are root-absolute (`/img/…`), so **use a repo named `<user>.github.io`** (served at the root) or attach the custom domain right away — both avoid sub-path breakage. Recommended: attach `www.uracquet.com` at first deploy, since it takes minutes to reverse.
